从 Codex 官方服务切换到 sub2api，或从其他中转站切换后，有时会发现原来的会话列表不见了。大多数情况下会话并没有被删除，而是新配置使用了不同的 Codex 数据目录，或者客户端尚未重新加载会话索引。

> **核心原则：** 官方服务、sub2api 和其他中转站应共用同一个 `CODEX_HOME`。切换时只修改供应商、Base URL、API Key 和模型，不要同时更换会话目录。

## 一、会话保存在什么位置

Codex 默认把会话保存在当前用户的 `.codex` 目录中。

| 系统 | 默认目录 |
| --- | --- |
| Windows | `C:\Users\你的用户名\.codex` |
| macOS / Linux | `~/.codex` |

与会话相关的主要内容包括：

| 文件或目录 | 用途 |
| --- | --- |
| `sessions` | 正常会话记录 |
| `archived_sessions` | 已归档会话 |
| `session_index.jsonl` | 会话列表索引 |

会话文件可能包含你的提示词、项目路径和模型回复，不要上传到公开网盘或发送给他人。

## 二、切换前先备份

1. 完全退出 Codex 客户端和所有 Codex 进程。
2. 找到当前正在使用的 `.codex` 目录。
3. 复制整个 `.codex` 目录到一个安全位置，并在备份名称中写明日期和当前供应商。
4. 确认备份中存在 `sessions` 目录，再开始切换。

不要在 Codex 仍然运行时复制数据库或索引文件，否则可能得到不完整的备份。

## 三、官方服务切换到 sub2api

1. 保留原来包含历史会话的 `.codex` 目录。
2. 使用 sub2api 一键导入 CC-Switch。
3. 只切换 `model_provider`、`base_url`、`api_key` 和 `model`。
4. `model_provider` 使用一键导入生成的 `OpenAI` 或 `customI`。
5. Base URL 使用用户中心显示的地址，不添加 `/v1`。
6. 在 CC-Switch 中点击 **启用**，然后重新启动 Codex 客户端。

只要客户端仍然使用原来的 `CODEX_HOME`，官方服务下创建的会话通常会继续显示。

## 四、从其他中转站切换到 sub2api

如果之前的中转站使用了单独的数据目录，请先找到旧目录。判断方法是查看哪个目录的 `sessions` 中包含切换前日期的文件。

### 旧目录有会话，新目录为空

1. 完全退出 Codex。
2. 备份旧目录和新目录。
3. 将旧目录中的 `sessions`、`archived_sessions` 和 `session_index.jsonl` 复制到当前使用的 `.codex` 目录。
4. 不要覆盖当前的 `auth.json` 和 `config.toml`，否则可能把供应商和登录状态切回旧配置。
5. 重新启动 Codex，等待客户端重新加载会话列表。

### 两个目录都有重要会话

不要直接用一个目录覆盖另一个目录。选择会话更完整的目录作为统一的 `CODEX_HOME`，先分别保留两份完整备份，再逐步合并 `sessions` 和 `archived_sessions`。存在同名文件时先保留两份，不要强制覆盖。

## 五、统一 CODEX_HOME

检查 Codex、CC-Switch、终端快捷方式和启动脚本是否设置了不同的 `CODEX_HOME`。

- 没有特殊需求时，建议使用系统默认的 `.codex` 目录。
- 如果必须自定义目录，所有启动方式都应使用同一个绝对路径。
- 切换供应商时不要修改 `CODEX_HOME`。
- Windows 下不要分别用普通权限和管理员权限运行 CC-Switch 与 Codex，以免写入不同用户目录。

统一目录后，今后在官方服务、sub2api 和其他中转站之间切换，只需更新供应商配置，会话文件仍保留在同一位置。

## 六、会话仍然不显示怎么办

按以下顺序检查：

1. 确认当前 `.codex/sessions` 中确实存在旧日期的会话文件。
2. 检查会话是否被移动到 `archived_sessions`。
3. 确认 `session_index.jsonl` 来自同一份会话目录。
4. 完全退出 Codex 后再重新启动，不要只关闭窗口。
5. 确认切换前后使用的是同一个系统用户和同一个 `CODEX_HOME`。
6. 如果客户端刚升级，先使用升级前的完整备份恢复，再重新启用当前供应商。

不要在客户端运行时单独覆盖 `.sqlite`、`.db`、`-wal` 或 `-shm` 文件。这些文件可能正被占用，强行替换容易损坏本地状态。

## 七、以后如何避免会话丢失

- 固定使用一个 `CODEX_HOME`。
- 每次切换供应商前备份整个 `.codex` 目录。
- 切换前彻底退出 Codex，切换后重新启动。
- 只让 CC-Switch 或手动配置中的一种方式负责写入 `config.toml`。
- 不要把会话目录和供应商配置目录拆分到不同位置。

切换服务后会话暂时不显示时，先检查目录和索引，不要立即删除或重装客户端。只要原会话文件仍在，通常都可以通过统一目录或恢复备份找回。
